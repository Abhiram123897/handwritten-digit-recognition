# ✍️ Handwritten Digit Recognition (CNN + MNIST)

A complete, end-to-end web application that recognizes handwritten digits (0–9).
A Convolutional Neural Network (CNN) trained on the MNIST dataset powers a Flask
backend, served through a modern, responsive UI with a drawing canvas, image
upload, a prediction dashboard, SQLite-backed history, and training
visualizations.

---

## ✨ Features

**Machine Learning**
- CNN built with TensorFlow/Keras, trained on MNIST.
- **≥ 98% test accuracy** (typically ~99%).
- Saves the model as `model/digit_model.h5` and a lightweight
  `model/digit_model.tflite` for fast, low-memory serving.
- Generates accuracy/loss curves, a confusion matrix, and a `metrics.json`.

**Backend (Flask)**
- Loads the model once at startup (prefers TFLite, falls back to `.h5`).
- REST API for prediction from **either** a drawing canvas or an uploaded file.
- Returns predicted digit, confidence score, and the full 0–9 probability
  distribution.
- SQLite history with list / clear / CSV export endpoints.

**Frontend / UI**
- Gradient background, professional card-based layout, fully responsive.
- Draw canvas (mouse + touch) with **Clear** and **Predict**, plus debounced
  **real-time prediction** as you draw.
- Drag-and-drop image upload with preview.
- Confidence progress bar and a Chart.js probability chart.
- Loading animations and a persistent **dark-mode** toggle.

**Dashboard**
- Prediction history table with thumbnail, digit, confidence, source, timestamp.
- Model performance metrics and training visualizations.
- Clear history and download history as CSV.

## 🏗️ Architecture

```
            ┌──────────────────────────────────────────────┐
            │                  Browser (UI)                 │
            │  index.html / dashboard.html + Bootstrap 5     │
            │  Canvas · Upload · Chart.js · Dark mode        │
            └───────────────┬───────────────▲───────────────┘
                 fetch /predict (JSON/form)  │ JSON result
                            ▼                │
            ┌──────────────────────────────────────────────┐
            │                 Flask (app.py)                 │
            │  /  /dashboard  /predict  /history  /metrics   │
            │  OpenCV preprocessing → MNIST-style 28×28       │
            │  ModelWrapper (TFLite preferred, .h5 fallback) │
            └──────┬───────────────────────┬────────────────┘
                   ▼                        ▼
         ┌──────────────────┐     ┌────────────────────┐
         │  model/*.tflite  │     │  database/history.db │
         │  model/*.h5      │     │  uploads/*.png       │
         └──────────────────┘     └────────────────────┘
                   ▲
                   │ produced by
         ┌──────────────────┐
         │     train.py     │  MNIST → CNN → evaluate → export
         └──────────────────┘
```

**Request flow:** the canvas exports a PNG data URL (or the user uploads a file)
→ Flask decodes it → OpenCV converts to grayscale, inverts, crops to the digit
and centers it on a 28×28 canvas → the model returns 10 class probabilities →
the API responds with the digit, confidence, and distribution, and logs the
prediction to SQLite.

## 🚀 Installation

Requires **Python 3.10–3.12**.

```bash
# 1. Clone / open the project folder
cd "hand written digit classifier"

# 2. Create and activate a virtual environment
python -m venv venv
# Windows:
venv\Scripts\activate
# macOS/Linux:
source venv/bin/activate

# 3a. To TRAIN the model, install the training dependencies (needs Python 3.10-3.12):
pip install -r requirements-train.txt

# 3b. To only RUN the app (serving), the lightweight runtime deps are enough:
pip install -r requirements.txt
```

> Two requirements files keep things lean:
> - **`requirements.txt`** — runtime only. Uses a tiny standalone TFLite runtime
>   (`ai-edge-litert`), no full TensorFlow. This is what Render installs, so the
>   app fits comfortably in the free tier's 512 MB RAM.
> - **`requirements-train.txt`** — adds TensorFlow/Keras, scikit-learn, and
>   Matplotlib/Seaborn, needed only to run `train.py`.
>
> If you plan to both train and run locally, just install
> `requirements-train.txt` (it includes the serving deps too).

## ▶️ How to Run

**1. Train the model** (produces `digit_model.h5`, `.tflite`, charts, metrics):

```bash
python train.py
```

Training runs ~12–15 epochs and typically reaches ~99% test accuracy.

**2. Start the app:**

```bash
# Development
python app.py
# -> open http://localhost:5000

# Production-style
gunicorn app:app --bind 0.0.0.0:5000
```

Open `http://localhost:5000` for the recognizer and
`http://localhost:5000/dashboard` for the dashboard.

## 🔌 API Reference

| Method | Endpoint          | Description |
|--------|-------------------|-------------|
| GET    | `/`               | Landing / prediction page |
| GET    | `/dashboard`      | Dashboard page |
| POST   | `/predict`        | Predict from canvas (JSON `{image}`) or upload (form `image`) |
| GET    | `/history`        | Prediction history (JSON) |
| POST   | `/history/clear`  | Clear all history |
| GET    | `/history/export` | Download history as CSV |
| GET    | `/metrics`        | Model performance metrics (JSON) |
| GET    | `/health`         | Health check |

```json
  "image_url": "/uploads/pred_20261024_171500_000000.png",
  "timestamp": "2026-10-24 17:15:00"
}
```

## ☁️ Deployment (Render)

This app is designed to run as a single, long-lived Flask service — ideal for
**Render** (Vercel/Netlify can't host a persistent Flask + TensorFlow server).

1. Push the project to a Git repository.
2. On Render: **New + → Blueprint**, and select this repo (it reads
   `render.yaml`).
3. Render runs `pip install -r requirements.txt` (lightweight runtime deps)
   and starts `gunicorn app:app`.
4. Commit a trained `model/digit_model.tflite` (and/or `.h5`) so the app can
   serve predictions, or run training as part of your build.

The free tier has 512 MB RAM and no persistent disk, so inference uses a tiny
standalone TFLite runtime (`ai-edge-litert`) — full TensorFlow is **not**
installed on the server. Note that on the free tier the SQLite history and
uploaded thumbnails reset on restart; add a paid persistent disk (or external
DB) if you need durable history.
