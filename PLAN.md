# Handwritten Digit Recognition — Project Plan

> End-to-end Handwritten Digit Recognition using a CNN (TensorFlow/Keras) on MNIST,
> served by a Flask app with a modern UI, dashboard, SQLite history, and data
> visualizations. Designed to run locally and deploy to Render.

---

## 1. Decisions (locked)

| Decision | Choice | Reason |
|---|---|---|
| Deployment target | **Render** (single Flask app) | Only option that runs the app as-is: warm model, persistent SQLite + uploads, no frontend/backend split. Vercel/Netlify can't host a persistent Flask + TensorFlow server. |
| Inference engine | **TFLite** (with `.h5` fallback) | Full TensorFlow needs ~500 MB+ RAM; Render free tier is 512 MB. TFLite model is a few hundred KB, loads instantly, fits free tier. Keras `.h5` still produced and used if `.tflite` missing. |
| Folder structure | **Flat** in current directory | Avoids double-nesting (`.../hand written digit classifier/handwritten-digit-classifier/`). |
| Training | **Attempt here**, fall back to local | Try to install TF + train to produce a real model and real charts. If env can't support it, user runs `train.py` (~3-5 min). |
| Real-time prediction | **Debounced draw + Predict button** | Predict-as-you-draw (debounced ~500ms) plus an explicit button. Best UX. |
| Model format | `.h5` (required) + `.tflite` (serving) | Satisfies spec and enables lightweight deployment. |

## 4. Machine Learning (`train.py`)

**Data pipeline**
1. Load MNIST via `keras.datasets.mnist`.
2. Reshape to `(N, 28, 28, 1)`, cast to float32.
3. Normalize pixels to `[0, 1]`.
4. One-hot encode labels (10 classes).
5. Small train/validation split for monitoring.

**CNN architecture (target >= 98% test accuracy)**
```
Input (28x28x1)
Conv2D(32, 3x3, relu) -> BatchNorm -> Conv2D(32, 3x3, relu) -> MaxPool(2x2) -> Dropout(0.25)
Conv2D(64, 3x3, relu) -> BatchNorm -> Conv2D(64, 3x3, relu) -> MaxPool(2x2) -> Dropout(0.25)
Flatten -> Dense(128, relu) -> Dropout(0.5) -> Dense(10, softmax)
```
- Optimizer: Adam | Loss: categorical_crossentropy | Metric: accuracy
- Epochs: ~12-15 (with early stopping) — reliably reaches 99%+ on MNIST
- Optional light data augmentation (small rotation/shift) for robustness

**Outputs**
- `model/digit_model.h5` (Keras)
- `model/digit_model.tflite` (converted for serving)
- `static/images/accuracy_loss.png` (train vs val accuracy & loss)
- `static/images/confusion_matrix.png` (seaborn heatmap)
- `model/metrics.json` (test accuracy, loss, per-class precision/recall, train timestamp)

**Evaluation**
- Report test accuracy & loss, assert >= 98%.
- Confusion matrix + classification report via scikit-learn.

## 5. Backend (`app.py`)

**Startup**
- Load TFLite interpreter (preferred) or Keras `.h5` fallback — chosen once at startup.
- Initialize SQLite (`database/history.db`) and create `history` table if missing.
- Ensure `uploads/` exists.

**Preprocessing (shared for canvas + upload)**
- Decode image (base64 data URL from canvas, or uploaded file via OpenCV/Pillow).
- Convert to grayscale, invert if needed (MNIST is white-on-black).
- Find bounding box of the digit, crop, center on 28x28 with padding (MNIST-style centering).
- Normalize to `[0,1]`, reshape to `(1,28,28,1)`.

**Endpoints**
| Method | Route | Purpose |
|---|---|---|
| GET  | `/` | Landing page (index.html) |
| GET  | `/dashboard` | Dashboard page |
| POST | `/predict` | Accept canvas data URL **or** uploaded file; return prediction |
| GET  | `/history` | Return prediction history (JSON) |
| POST | `/history/clear` | Clear all history |
| GET  | `/history/export` | Download history as CSV |
| GET  | `/metrics` | Return model metrics JSON (for dashboard) |
| GET  | `/health` | Health check (for Render) |

**/predict response**
```json
{
  "digit": 7,
  "confidence": 0.9987,
  "probabilities": [0.0001, 0.0, ..., 0.9987, ...],  // length 10
  "image_url": "/uploads/pred_20261024_171500.png",
  "timestamp": "2026-10-24 17:15:00"
}
```

**History record (SQLite)**
`id, predicted_digit, confidence, image_path, timestamp`

**Robustness**
- Validate file type/size; handle empty canvas; try/except with JSON error responses.
- CORS enabled (harmless locally; useful if frontend ever split out).

## 6. Frontend / UI

**index.html (landing + predict)**
- Gradient hero/landing section, professional card-based layout.
- Navbar with links (Home / Dashboard) and **dark mode toggle** (persisted in localStorage).
- Draw card: HTML5 canvas (mouse + touch), **Clear** button, **Predict** button, debounced predict-as-you-draw.
- Upload card: file input + **drag-and-drop** zone + **image preview**.
- Results card: predicted digit (big), **confidence progress bar**, **Chart.js bar chart** of class probabilities (0-9), **loading spinner** during requests.
- Fully mobile responsive (Bootstrap 5 grid + custom media queries).

**dashboard.html**
- **Prediction history table**: thumbnail image, predicted digit, confidence, timestamp.
- **Clear history** button and **Download CSV** button.
- **Model performance metrics** cards (test accuracy, loss).
- **Accuracy/loss graph** image and **confusion matrix** image.

**style.css**
- CSS variables for light/dark themes, gradients, card shadows, animations (fade-in, button hover), spinner, responsive breakpoints.

**script.js / dashboard.js**
- Canvas drawing logic, base64 export, fetch to `/predict`, render results + chart.
- Drag-and-drop + preview, dark mode toggle, debounce helper.
- Dashboard: fetch `/history` + `/metrics`, build table, CSV download, clear action.
